# Anfas Backend

NestJS 12 + Node.js 24 + отдельная PostgreSQL 17. Strapi остаётся отдельной CMS и не участвует в регистрации пользователей.

Первый этап: регистрация по email/паролю, вход, текущий пользователь и выход. Любой зарегистрированный пользователь получает доступ к калькулятору. Добавлен небольшой кабинет с личными сохранёнными сметами.

## Локальный запуск

Нужны Node.js 24, pnpm 11 и работающий Docker Desktop.

```powershell
Set-Location 'C:\Users\1\Desktop\Работа anfas\anfas-backend'
# Только при первом запуске; существующий .env не перезаписывать.
Copy-Item .env.example .env
pnpm install
pnpm db:up
pnpm dev
```

API: http://127.0.0.1:3000/api/health. PostgreSQL: 127.0.0.1:5433, база `anfas_backend`. Учётные данные в `.env` предназначены исключительно для локальной разработки. База Strapi `anfas_cms` на 5432 не используется этим приложением.

Данные сохраняются в отдельном Docker volume `anfas-backend_anfas_backend_pgdata`. `pnpm db:down` останавливает контейнер, сохраняя volume. Не запускать `docker compose down -v`, если нужно сохранить пользователей.

Таблицы `users`, `sessions` и `estimates` создаются идемпотентно при старте. Перед серверным размещением и дальнейшими изменениями схемы нужно добавить версионируемые миграции.

## API

| Метод | URL | Назначение |
| --- | --- | --- |
| GET | `/api/health` | Готовность HTTP-сервиса |
| POST | `/api/auth/register` | Создать пользователя и сразу войти |
| POST | `/api/auth/login` | Войти |
| GET | `/api/auth/me` | Получить `{ user: { id, email, createdAt } }`; без сессии 401 |
| POST | `/api/auth/logout` | Отозвать текущую сессию и удалить cookie |

Регистрация и вход принимают JSON `{ "email": "user@example.com", "password": "пароль от 10 символов" }`. Email нормализуется: trim + lowercase. Пароль от 10 до 128 символов. Повторный email → 409, неверные данные входа → 401, некорректное тело → 400, превышение лимита → 429.

POST, PATCH и DELETE требуют `Content-Type: application/json`, `X-Anfas-Client: web` и `Origin` из `FRONTEND_ORIGINS`. Фронтенд отправляет эти запросы через Vite proxy, с одного origin. Для локальной проверки открывать сайт именно на http://127.0.0.1:5173; не смешивать localhost и 127.0.0.1 в одном сеансе.

## Сессии и границы этапа

- Пароли хешируются асинхронным scrypt с индивидуальной случайной солью; сравнение constant time.
- В cookie только случайный токен, в БД его SHA-256-хеш. Пароли/хеши/токены не возвращаются в JSON.
- Cookie `anfas_session`: HttpOnly, SameSite=Strict, Path=/api, абсолютный срок 8 часов. В `NODE_ENV=production` также Secure.
- Выход отзывает сессию в БД. Пользователи и действующие сессии сохраняются после перезапуска API.
- Вход и регистрация ограничены 10 запросами в минуту на IP для каждого маршрута; общий лимит 120. Счётчики сейчас в памяти одного процесса.
- Подтверждения email, восстановления пароля и ролей на этом этапе нет.
- В NestJS-режиме личные сметы сохраняются в PostgreSQL. Прежний общий черновик браузера не используется кабинетом; предложение его переноса убрано по решению пользователя.

## Проверки

```powershell
pnpm check
pnpm build
pnpm test
```

Тесты требуют PostgreSQL, создают случайную отдельную схему `anfas_auth_test_*` и удаляют только её после проверки. Рабочие таблицы `public` не изменяются. Проверяются анонимный доступ, валидация, CSRF, нормализация email, cookie, отсутствие секретов в ответах, дубликаты, неверный пароль, перезапуск, выход, истечение, подделка токена, конкурентная регистрация и rate limit.

## Перед будущим размещением

Потребуются HTTPS, отдельные production-секреты и БД, резервное копирование, proxy `/api/*` к NestJS и осознанная настройка доверенного proxy/IP для rate limit. На фронтенде существующий PHP-gate закрытых calculator assets пока сохранён; при переходе на Node нужно согласовать его с новой сессией. Текущая локальная проверка использует Vite и не подтверждает серверную защиту статических JS/CSS.

Справочная документация: [NestJS rate limiting](https://docs.nestjs.com/security/rate-limiting), [PostgreSQL](https://www.postgresql.org/docs/17/tutorial.html).

## Личные сметы

| Метод | URL | Назначение |
| --- | --- | --- |
| GET | `/api/estimates` | Метаданные только своих смет |
| POST | `/api/estimates` | Создать: `{ title, payload }` |
| GET | `/api/estimates/:id` | Открыть свою смету целиком |
| PATCH | `/api/estimates/:id` | Сохранить: `{ title, payload, revision }` |
| DELETE | `/api/estimates/:id` | Удалить: `{ revision }`, ответ 204 |

`payload` содержит снимок калькулятора v2, реквизиты документа и индивидуальный прайс (`priceProfile`, либо null). Сохранение явное. Название 1–120 символов, снимок до 1 МБ. Владельца определяет сессия, передать чужой userId нельзя. Чужая/отсутствующая смета → 404, нет сессии → 401. Сохранённые цены не пересчитываются сервером.

`revision` увеличивается после изменения. Устаревшее сохранение/удаление → 409: нужно открыть актуальную версию или обновить список. Отдельные PostgreSQL-тесты `anfas_estimates_test_*` проверяют двух владельцев, запрет чужого CRUD, валидацию, CSRF, конфликт версий, перезапуск и удаление. Всего 13 API-тестов вместе с авторизацией.

## Копирование и избранное

POST `/api/estimates/:id/copy` с JSON `{}` создаёт самостоятельную копию сохранённой сметы: полный снимок, реквизиты и прайс, новый UUID/revision=1, название до 120 символов с окончанием « — копия». Номер документа тоже копируется — при необходимости пользователь меняет его. Копия не отмечается избранной. Чужой ID → 404.

PATCH `/api/estimates/:id/favorite` принимает `{ isFavorite: boolean }`, проверяет сессию/владельца и сохраняет отметку в PostgreSQL. Отметка не меняет revision и время изменения содержимого, поэтому не вызывает ложный конфликт правок. Старые строки автоматически получают false при идемпотентном добавлении столбца. Список возвращает isFavorite, number, date, estimator наряду с object/customer.

## Переименование из списка

PATCH `/api/estimates/:id/title` принимает `{ title, revision }`. Название обрезается по краям и проверяется на 1–120 символов. Сервер проверяет владельца и актуальную revision; чужая смета → 404, устаревшая версия → 409. Меняются только title/revision/updatedAt, снимок, реквизиты и избранное остаются прежними. Отдельный PostgreSQL-тест проверяет эти условия.
